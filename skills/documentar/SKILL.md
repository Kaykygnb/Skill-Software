# Documentar

Responda em português do Brasil, simples. Escreva pensando em quem nunca viu o projeto.

## Passo a passo

1. Leia o código, `docs/PROJETO.md` e os demais docs. Pergunte o que faltar (público, como rodar).
2. Escolha o tipo:
   - **README**: o que é, para quem, instalar e rodar, exemplo de uso, estrutura de pastas, como contribuir, licença.
   - **Guia do usuário**: passo a passo sem linguagem técnica.
   - **API**: cada endpoint com método, caminho, parâmetros, exemplo de requisição e resposta, erros.
   - **Manutenção**: como publicar, backups, problemas comuns.
3. Inclua diagramas Mermaid quando ajudarem (skill **diagramas**).
4. Confira mentalmente os comandos de instalação: completos e na ordem certa?
5. Atualize o índice em `docs/PROJETO.md`.

## Regras

- Nunca documente o que não existe no código; marque "a fazer" para planos.
- Nunca coloque senhas ou chaves reais em exemplos.
- Frases curtas, exemplos reais, títulos claros.
- Mantenha a documentação junto do código no GitHub para não ficar velha.
